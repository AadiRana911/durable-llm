# llmrun — design contract

This file is the **binding interface contract**. Every module is implemented against it.
If an implementation disagrees with this document, this document wins.

## What llmrun is

Run multi-step LLM pipelines that survive crashes, don't double-bill on retry, and can't
silently blow a budget. State lives in Postgres. No new infrastructure.

## Non-goals (state these in the README too)

- Not an agent framework, no orchestration DSL, no prompt management
- No web UI (CLI only)
- Exactly two provider adapters: one real (Anthropic), one deterministic fake (echo)
- Four tables. If a fifth is needed, the scope crept.

## Stack

- Python **>= 3.11**, `src/` layout, hatchling build backend, managed with `uv`
- Postgres 17 via `psycopg` 3 (sync). No ORM, no Alembic.
- Stdlib `argparse` for CLI. No click, no typer.
- Core has **zero** provider dependencies. `anthropic` is an optional extra.
- Money is always `decimal.Decimal`. Never float.
- Timestamps are `timestamptz`, always UTC, always generated by Postgres (`now()`).

## Schema (`migrations/*.sql`)

Four tables, including `schema_migrations`. The DDL below is the effective schema after all
three current migrations: `0001_initial.sql` creates the base tables,
`0002_attempt_ceiling.sql` adds `failures` and `max_attempts`, and
`0003_integrity_and_pacing.sql` adds retry pacing, migration checksums, provider latency,
database constraints, and the final indexes. Migrations are additive files rather than edits
to an applied one, so a database that has already run `llmrun migrate` stays correct.

All ids are `uuid` generated with `gen_random_uuid()` (`pgcrypto` is not required on
PG 13+; `gen_random_uuid()` is built in).

```sql
CREATE TABLE schema_migrations (
    version     text PRIMARY KEY,
    applied_at  timestamptz NOT NULL DEFAULT now(),
    checksum    text
);

CREATE TABLE runs (
    id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    pipeline     text        NOT NULL,
    tenant_id    text        NOT NULL,
    status       text        NOT NULL,          -- see RunStatus
    input        jsonb       NOT NULL DEFAULT '{}'::jsonb,
    output       jsonb,
    budget_usd   numeric(12,6),                 -- NULL = unlimited
    spent_usd    numeric(12,6) NOT NULL DEFAULT 0,
    error_class  text,
    error_detail text,
    attempt      integer     NOT NULL DEFAULT 0,   -- claims, incl. lease steals
    failures     integer     NOT NULL DEFAULT 0,   -- recorded verdicts only
    max_attempts integer     NOT NULL DEFAULT 5,   -- copied from the pipeline at enqueue
    locked_by    text,
    locked_at    timestamptz,
    created_at   timestamptz NOT NULL DEFAULT now(),
    updated_at   timestamptz NOT NULL DEFAULT now(),
    next_attempt_at timestamptz,
    CONSTRAINT runs_status_chk CHECK (
        status IN ('queued', 'running', 'succeeded', 'failed',
                   'pending_review', 'halted_budget')
    ),
    CONSTRAINT runs_error_class_chk CHECK (
        error_class IS NULL
        OR error_class IN ('transient', 'malformed', 'policy', 'budget', 'permanent')
    ),
    CONSTRAINT runs_money_chk CHECK (
        spent_usd >= 0 AND (budget_usd IS NULL OR budget_usd >= 0)
    ),
    CONSTRAINT runs_counters_chk CHECK (
        attempt >= 0 AND failures >= 0 AND max_attempts >= 1
    )
);
CREATE INDEX runs_claim_idx ON runs (created_at)
    WHERE status IN ('queued', 'running');
CREATE INDEX runs_created_idx ON runs (created_at DESC);
CREATE INDEX runs_id_prefix_idx ON runs ((id::text) text_pattern_ops);
CREATE INDEX runs_next_attempt_idx ON runs (next_attempt_at)
    WHERE next_attempt_at IS NOT NULL;
CREATE INDEX runs_tenant_idx ON runs (tenant_id, created_at DESC);

CREATE TABLE steps (
    run_id       uuid        NOT NULL REFERENCES runs(id) ON DELETE CASCADE,
    name         text        NOT NULL,
    status       text        NOT NULL,          -- see StepStatus
    input_hash   text        NOT NULL,
    output       jsonb,
    attempt      integer     NOT NULL DEFAULT 0,
    error_class  text,
    error_detail text,
    started_at   timestamptz NOT NULL DEFAULT now(),
    ended_at     timestamptz,
    PRIMARY KEY (run_id, name),
    CONSTRAINT steps_status_chk CHECK (status IN ('running', 'succeeded', 'failed')),
    CONSTRAINT steps_attempt_chk CHECK (attempt >= 0)
);

CREATE TABLE llm_calls (
    id          uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
    run_id      uuid        NOT NULL REFERENCES runs(id) ON DELETE CASCADE,
    step_name   text        NOT NULL,
    attempt     integer     NOT NULL DEFAULT 0,
    input_hash  text        NOT NULL,
    model       text        NOT NULL,
    tokens_in   integer     NOT NULL DEFAULT 0,
    tokens_out  integer     NOT NULL DEFAULT 0,
    cost_usd    numeric(12,6) NOT NULL DEFAULT 0,
    cached      boolean     NOT NULL DEFAULT false,
    response    jsonb,                          -- {"text": ..., "model": ...}
    created_at  timestamptz NOT NULL DEFAULT now(),
    duration_ms integer,
    CONSTRAINT llm_calls_tokens_chk CHECK (
        tokens_in >= 0 AND tokens_out >= 0 AND cost_usd >= 0
    ),
    CONSTRAINT llm_calls_duration_chk CHECK (duration_ms IS NULL OR duration_ms >= 0),
    CONSTRAINT llm_calls_cached_free_chk CHECK (NOT cached OR cost_usd = 0)
);
CREATE UNIQUE INDEX llm_calls_cache_idx
    ON llm_calls (run_id, input_hash) WHERE cached = false;
CREATE INDEX llm_calls_run_idx ON llm_calls (run_id, created_at);
```

`llm_calls` is both the **cost ledger** and the **idempotency store**. A row with
`cached=false` is a real billed provider call and holds the response; a row with
`cached=true` is a replay, costs 0, and records that a retry was absorbed.

Checksums are nullable because rows for migrations applied before `0003` have no digest that
was observed at application time. The runner does not invent one retrospectively.

## `errors.py` — the failure taxonomy

This is the centrepiece of the whole project. Naive implementations collapse all of this
into one `except`. Keep the five classes distinct and treat them differently.

```python
class ErrorClass(str, Enum):
    TRANSIENT = "transient"
    MALFORMED = "malformed"
    POLICY    = "policy"
    BUDGET    = "budget"
    PERMANENT = "permanent"

class LLMRunError(Exception):
    error_class: ClassVar[ErrorClass]

class TransientError(LLMRunError):        # timeout, 429, 5xx, connection reset
class MalformedOutputError(LLMRunError):  # response did not satisfy `schema`
class PolicyRefusalError(LLMRunError):    # provider refused; retrying is pointless
class BudgetExceededError(LLMRunError):   # projected spend exceeds the cap
class PermanentError(LLMRunError):        # bug in pipeline code

def classify(exc: BaseException) -> ErrorClass:
    """LLMRunError -> its class; anything else -> PERMANENT."""
```

Disposition table — implemented as `DISPOSITIONS: dict[ErrorClass, Disposition]`, consumed
by `worker.py` and `context.py`. Do not hardcode this logic in two places.

| class     | retry? | strategy                  | max attempts | terminal run status |
|-----------|--------|---------------------------|--------------|---------------------|
| transient | yes    | exponential backoff + jitter | 5         | `failed`            |
| malformed | yes    | repair prompt (in-step)   | 2            | `pending_review`    |
| policy    | no     | —                         | 0            | `pending_review`    |
| budget    | no     | —                         | 0            | `halted_budget`     |
| permanent | no     | —                         | 0            | `failed`            |

```python
@dataclass(frozen=True)
class Disposition:
    retry: bool
    max_attempts: int
    terminal_status: RunStatus
    backoff_base_seconds: float = 1.0
```

## `cache.py`

```python
def canonical_json(value: Any) -> str:
    """The one JSON form llmrun hashes: sort_keys=True, separators=(",", ":"),
    ensure_ascii=False, and a type-tagged fallback — a value JSON cannot represent
    natively becomes {"__type__": type(o).__name__, "__str__": str(o)}."""

def prompt_json(value: Any) -> str:
    """The same canonical shape with a plain default=str. Prompt text, not key
    material: what a model reads, and what the cost projection is measured against."""

def input_hash(step: str, payload: Any, model: str, params: Mapping[str, Any]) -> str:
    """sha256 hex over canonical_json({step, payload, model, params}).
    Deterministic across processes and runs."""
```

**The fallback carries the type name, and the two renderers are not interchangeable.** A
bare `default=str` — which this was — is type-blind: `Decimal("1")`, the string `"1"` and a
`UUID` whose text happens to match all collapse to the same characters, so two genuinely
different calls compute one key and the second is served the first's stored response. That
is not a missed cache, it is a **wrong answer**, delivered confidently, with a ledger row
saying it was a legitimate replay. The tag separates them at no cost to the crash-proofing
the fallback was there for in the first place.

But the same function was also rendering the payload a model reads, and prompt text wants
the opposite: `{"amount":{"__str__":"1.50","__type__":"Decimal"}}` shows the model llmrun's
bookkeeping instead of the number and charges for the extra tokens. Hence `prompt_json`,
which keeps the old rendering for the one caller that needs it — `llm()` builds its
`payload_text` with it, while the key is computed from the payload *object* with
`input_hash`. Same canonical shape, different fallback, and the difference is deliberate:
one must never merge two values, the other has no such requirement.

Two consequences worth stating plainly. Adopting the tag changed the bytes fed to the hash,
so every key computed by an earlier version is unreachable — an existing database misses
once per distinct call and re-bills it, then replay resumes; nothing is corrupted and no
migration is needed. And one collision survives on purpose: a payload containing the literal
dict `{"__type__": "Decimal", "__str__": "1"}` hashes as `Decimal("1")` does, because the tag
is ordinary data. Closing that would mean escaping every dict in every payload, invalidating
every key a second time, to defend against a shape nobody writes by accident.

Cache lookup lives in `context.py`, scoped to the run:

```sql
SELECT response, model, tokens_in, tokens_out FROM llm_calls
WHERE run_id = %s AND input_hash = %s AND cached = false
ORDER BY created_at LIMIT 1
```

The token counts come back with the response because the `cached=true` row copies them: a
saving you cannot quantify is a saving that gets argued with, and `llmrun costs` prices
what the ledger avoided from exactly these numbers.

A hit writes a new `llm_calls` row with `cached=true, cost_usd=0` and returns the stored
response. This is what makes "a crash between the API response and the DB commit does not
bill you twice" true rather than aspirational.

A billed row whose response has no usable string `text` is not a cache hit: serving it would
turn corrupted or hand-edited state into a trusted checkpoint. The provider is called again.
Because the unique billed-call identity already occupies that key, this exceptional recovery
path repairs that one unusable row in place and *adds* the replacement call's cost to the
existing cost. Valid ledger rows remain append-only, and spend never forgets either call.

Two properties of that lookup are load-bearing and were each worth one money-losing bug:

* **`ORDER BY created_at LIMIT 1` is only correct because each key holds at most one billed
  row.** Every round of the repair sequence gets its own `input_hash` (see `llm()` below),
  so "oldest" and "newest" are the same row. If several billed rows could share a key, the
  oldest is by construction the one that was already rejected.
* **The lookup runs twice**: once in its own transaction, before the budget check, so a
  replay is free and cannot be blocked by an exhausted cap; and once *inside* the
  transaction that holds the run's row lock, immediately before the provider call. The
  first one is what makes resumption cheap. The second is what makes two overlapping
  workers safe — without it, the loser of the lock race decides "miss" while the winner's
  row is still uncommitted, and acts on that stale decision after the lock is released.

## `budget.py`

```python
def project_cost(model: str, prompt_chars: int, max_tokens: int) -> Decimal
    """Worst case: estimate input tokens as ceil(prompt_chars / 4), assume max_tokens out."""

def check_budget(conn, run_id: UUID, projected: Decimal) -> None
    """SELECT budget_usd, spent_usd FOR UPDATE. If budget is not NULL and
    spent + projected > budget: raise BudgetExceededError. Enforced BEFORE the call."""

def record_spend(conn, run_id: UUID, amount: Decimal) -> None

def budget_overrun(conn, run_id: UUID) -> Decimal | None
    """Post-flight half of the guard: how far the *recorded* spend is past the cap, or
    None. `project_cost`'s chars/4 estimate under-counts anything that is not English
    prose, and the provider may report a pricier model than the one projected, so the
    cap is re-checked against the real cost in the same transaction as the ledger row.
    Returns rather than raises: the caller must commit the receipt for money already
    spent, then halt before the *next* call. Residual exposure: one call."""
```

## `migrate.py`

Applies `migrations/*.sql` in filename order, with one transaction per file, recording the
filename stem in `schema_migrations`. A session-level Postgres advisory lock covers the whole
operation so concurrent starters cannot apply the same migration. Once `0003` has added the
column, newly applied migrations also record the SHA-256 of their SQL; a non-null recorded
checksum that differs from the file is a hard error. Pre-`0003` rows remain null because no
digest was observed when they were applied. A database version absent from the checkout is a
warning that the database may be ahead.

Migration lookup checks, in order, `LLMRUN_MIGRATIONS_DIR`, the files bundled inside an
installed wheel, and the repository-level `migrations/` directory for source checkouts.
Re-running against an up-to-date database is a no-op.
`def migrate(conn, migrations_dir: Path | None = None) -> list[str]` returns applied versions.

### `step()` semantics

1. Compute `h = input_hash(name, (args, kwargs), "-", {})`.
2. `SELECT` the `steps` row. If it exists with `status='succeeded'` **and** `input_hash = h`,
   return its stored `output` without executing — **this is resumption**.
   If it exists with a *different* hash, the inputs changed: re-execute and overwrite.
3. Otherwise, verify this context still owns the run, renew `locked_at`, and upsert
   `status='running'` in the same transaction. Run `fn`, then verify ownership and renew the
   lease again while committing `status='succeeded'` with the JSON-serialised output.
   **Commit before returning** — an uncommitted step is a lost step.
4. On exception: verify ownership without renewing the lease, record
   `error_class`/`error_detail`, mark `failed`, and re-raise. A failure is not progress.

These checkpoint transactions renew a lease on forward progress; there is no background
heartbeat while a step body is running. `lease_seconds` must therefore exceed the slowest
single step, even when a multi-step run lasts much longer than one lease period.

### `llm()` semantics

Same checkpointing as `step()`, wrapping this sequence. Steps 2–6 are a loop: one pass per
answer examined, with `n` the 0-based round number.

1. `h = input_hash(name, payload, model, params)`, where `params` are the **effective** call
   parameters — `**params` plus `max_tokens`, `prompt`, and `repair_round: n`. All three
   additions are corrections of real bugs, not embellishment:
   * `max_tokens` changes what the model may produce.
   * `prompt` is the input that most determines the answer. Omitting it means editing an
     instruction and resuming an in-flight run serves the *old* instruction's answer, with
     no error and no evidence. Note the narrower hazard no hash can close: `step()` hashes
     `(name, args, kwargs)` and not `fn`, so a changed function body — or a zero-argument
     closure — still replays stale output.
   * `repair_round` separates a malformed answer from the repair bought to replace it.
     Under one key, a resume replays the unusable answer and re-buys the repair every time.
   The step checkpoint is keyed on round 0, so a prompt edit invalidates it too.
2. Cache lookup by `(run_id, h)`. Hit → write a `cached=true` row, cost 0, skip to step 6.
3. `check_budget(conn, run_id, project_cost(...))` — **before** the network call. Behind the
   same row lock, re-read the ledger (see `cache.py` above) and re-check `runs.locked_by`
   against this context's `worker_id`: a worker whose lease has been stolen must abandon the
   run rather than spend against one another worker now owns.
4. `provider.complete(...)`. Provider maps SDK failures to `TransientError` /
   `PolicyRefusalError`. Transient errors retry with exponential backoff + jitter per the
   disposition table, **inside** the step.
5. Immediately `INSERT` an `llm_calls` row (`cached=false`, real cost) and
   `record_spend()` **in the same transaction**, then commit. Never make a second call
   before the first is durably recorded. In that same transaction, `budget_overrun()`
   compares the *actual* spend against the cap; if it is over, raise `BudgetExceededError`
   **after** the commit, so the receipt survives and the run halts before the next call.
6. If `schema` is given, `json.loads` the text and call `schema(parsed)`. Any exception →
   `MalformedOutputError`. Retry up to 2 attempts with the validation error appended to the
   prompt (the **repair loop**), incrementing `n` and returning to step 2 — so a repair that
   was already bought and recorded is replayed rather than re-purchased. On final failure
   the run ends `pending_review`, not `failed`.
7. Return the parsed object, or the raw text when `schema is None`.

`schema` is any callable that takes decoded JSON and returns a validated object, raising on
invalid input. Pydantic users pass `Model.model_validate`. No pydantic dependency.

## `providers/echo.py`

Deterministic, offline, no API key. `complete()` returns JSON derived from
`sha256(payload)` so results are stable across processes; token counts derived from string
lengths. Supports test hooks via constructor args:

- `fail_at: dict[str, Exception] | None` — raise a given error the first time a step name is seen
- `always_fail_at: dict[str, Exception] | None` — raise on *every* call for that step. The
  counterpart to `fail_at`'s one-shot entry, and the only way to drive the in-step transient
  retry budget (`DISPOSITIONS` gives `TransientError` five calls inside one `_billed_call`)
  to exhaustion: with a hook that fires once, the branch where llmrun stops retrying and lets
  the step fail is unreachable from a test. Checked before `fail_at` and never consumes its
  entry, so a step named in both fails forever rather than failing twice and recovering.
- `latency_seconds: float = 0.0`
- `malformed_steps: Iterable[str] | Mapping[str, int] | None` — emit invalid JSON to exercise
  the repair loop. The two forms are not interchangeable: a bare iterable of names means
  "malformed on every attempt", which drives the repair budget to exhaustion and ends the run
  `pending_review`, while `{step: n}` means "malformed for the first *n* attempts, then valid"
  — the only form that exercises a repair which actually *succeeds*. Documenting this as a
  plain `set` hid the branch where the repair loop recovers.

The echo provider is what makes `make demo` and the chaos suite run with **zero API keys**.
This matters: a reviewer must be able to clone and run in 90 seconds.

## `providers/anthropic.py`

Real adapter, lazily importing the `anthropic` SDK (optional extra). Default model
`claude-sonnet-5`. Read token counts from `response.usage`. Map
`RateLimitError`/`APIConnectionError`/`APITimeoutError`/`InternalServerError` →
`TransientError`; a refusal stop reason → `PolicyRefusalError`; everything else →
`PermanentError`. Do not retry inside the adapter — retry policy belongs to `context.py`.

## `worker.py`

Claim with a lease so a killed worker's run is reclaimed rather than stranded:

```sql
UPDATE runs
SET status='running', locked_by=%s, locked_at=now(), attempt=attempt+1,
    next_attempt_at=NULL, updated_at=now()
WHERE id = (
    SELECT id FROM runs
    WHERE attempt < max_attempts
      AND (next_attempt_at IS NULL OR next_attempt_at <= now())
      AND (status='queued'
           OR (status='running' AND locked_at < now() - make_interval(secs => %s)))
    ORDER BY created_at
    FOR UPDATE SKIP LOCKED
    LIMIT 1
)
RETURNING *;
```

`FOR UPDATE SKIP LOCKED` is what makes concurrent *claims* safe. Say so in a comment — and
say what it does not do: it prevents two workers taking the same row in the same instant, not
two workers executing the same run because a lease expired while its holder was still
working. That case is handled by the fencing check in `context.py` step 3, plus the ledger
re-read behind the same lock. Starting and successfully checkpointing a step also renew the
lease, so a run making visible progress is not stolen merely because its total duration exceeds
one lease period. There is deliberately no timer heartbeat during a step body.

`attempt < max_attempts` is the ceiling on **executions**, and it has to be enforced here
because a SIGKILLed worker never reaches the code that writes a verdict. A companion sweep,
run by default for direct `run_once` calls and once per 60-second sweep interval in `run_forever`,
moves a queued run at its ceiling, or a running run at its ceiling whose lease has expired, to
`failed` with `error_class='permanent'`. Otherwise those rows are unclaimable but still look
like work in progress. The sweep is capped at 100 rows per transaction.

```python
def run_once(conn, *, worker_id: str, lease_seconds: int = 60, provider: Provider,
             default_model: str | None = None, sweep: bool = True) -> UUID | None
def run_forever(conn, *, provider: Provider, poll_interval: float = 1.0, ...) -> None
```

`run_forever` returns `None`, not `NoReturn`. Graceful shutdown is a requirement — on
SIGTERM the loop finishes the run it holds, writes the verdict, and returns so the caller
can close the connection — and a function that handles SIGTERM properly is by construction
a function that returns.

On completion: `succeeded` + output. On exception: classify, consult `DISPOSITIONS`. A
retryable run is returned to `queued` with a jittered `next_attempt_at` only if another failure
is allowed by the disposition, the run's stored ceiling, and the currently registered
pipeline; the lowest limit wins. Otherwise set the disposition's terminal status and record
`error_class`/`error_detail`. Handle SIGTERM gracefully (finish the current run, then exit);
SIGKILL is what the chaos test uses.

**Two counters, because one cannot do both jobs.** `attempt` counts claims and is
incremented by the claim query, so it bounds executions even when nothing survives to
report a failure. `failures` counts recorded verdicts and is incremented only by the verdict
statement, so it is what the retry budget is measured against. Measuring the retry budget
with `attempt` means a pipeline whose steps legitimately outlive `--lease-seconds` reaches
its first genuine transient error with the budget already spent, and is failed terminally
having never been retried once.

## `cli.py` (argparse, `llmrun` entry point)

```
llmrun migrate
llmrun worker [--once] [--import MODULE] [--provider echo|anthropic] [--lease-seconds N]
              [--poll-interval SECONDS] [--model MODEL] [--worker-id ID]
llmrun enqueue PIPELINE --tenant T --json '{"thread_id": "t1"}' [--import MODULE]
llmrun runs list [--tenant T] [--status S] [--limit N]
llmrun runs show RUN_ID          # run header, step table, per-call cost ledger
llmrun costs [--tenant T] [--since WHEN] [--until WHEN]
llmrun health                    # database reachability, migrations, queue and stranded work
```

`runs show` is the demo's money shot — it must clearly display which calls were cached.
`costs` defaults to the most recent 30 days; `--since` is inclusive and `--until` exclusive.

## Tests

`tests/conftest.py` — session fixture that connects using `LLMRUN_DATABASE_URL`, runs
migrations, and truncates tables between tests. **Skip the whole suite with a clear message
if Postgres is unreachable** rather than erroring.

- `test_cache.py` — hash determinism; key order and whitespace don't matter; different
  model/params differ; the digest survives a fresh interpreter with a hostile
  `PYTHONHASHSEED`, which is the only place a `str()`-of-a-set leak would show. Plus the
  two-renderer split: `canonical_json` must carry the type tag (or `Decimal("1")` and `"1"`
  share an idempotency key) and `prompt_json` must not (or every prompt containing an exotic
  type is rewritten and re-billed). The two differ by one keyword argument, so the tests
  assert both renderings literally — otherwise merging them back reads like removing duplication
- `test_cost.py` — Decimal precision, rounding, unknown-model KeyError
- `test_providers.py` — the Anthropic adapter's silent-failure paths, with the SDK stubbed out
  in **two** shapes. An empty stub is the degraded SDK, where the HTTP status code is the whole
  signal; a populated one carries exception classes named like the real SDK's and deliberately
  gives them no `status_code`, so a passing classification proves the name lookup fired rather
  than the backstop underneath it. With only the empty stub, a typo in
  `_TRANSIENT_EXCEPTION_NAMES` turned every rate limit into a hard failure and nothing noticed.
  Also the constructor — `max_retries=0` and the 45s timeout, which no test reached while every
  test passed `client=` — and that a dropped caller param warns while the framework-injected
  `step` key stays silent
- `test_errors.py` — `classify()` for each class; disposition table completeness (every
  `ErrorClass` has an entry); backoff shape rather than exact numbers. Plus the defensive
  branches on the money path, which nothing else in the suite executes: `_price`'s fallback
  when a provider answers under an unregistered model id (a fallback quietly returning zero
  makes every run look free and the budget cap never fire), the replay guard that refuses to
  serve a ledger row with no usable text, and the cap on both untrusted strings a repair
  prompt quotes back
- `test_budget.py` — halts before the call; boundary case where projected spend exactly equals
  budget; and the post-flight half, which nothing else can catch: a call whose input was
  under-projected halts the run rather than reporting success, keeps the ledger row and the
  spend for the money already gone, and stops after that one call
- `test_pipeline.py` — resumption returns stored output without re-executing; changed input re-executes; repair loop; `pending_review` on policy refusal.
  Also the two intersections that each cost money and that neither of those alone catches:
  a crash *between a repair and its checkpoint* must not re-buy the repair, and editing a
  prompt must re-execute rather than replay the previous instruction's answer
- `test_worker.py` — the claim ceiling bounds executions; the sweep fails a run stranded
  past it (but not one still inside its lease); lease churn does not spend the retry
  budget; checkpoint progress renews the lease; a worker whose lease was stolen stops
  spending or overwriting checkpoints; two overlapping workers on two connections bill one
  call, not two
- `chaos/test_crash_resume.py` — **the credibility centrepiece**:
  1. run the 12-step example uninterrupted and record its output and billed-call count —
     the baseline — then reset the tables and enqueue the same work again
  2. start `llmrun worker` as a subprocess
  3. poll until ~half the steps are `succeeded` **and** `billed_calls >= succeeded_steps`,
     then `SIGKILL` the process group. The second condition is what aims the kill at the
     only window where the ledger is load-bearing: a provider call committed, its step not
     yet checkpointed. Polling on the step count alone fires *between* steps, where the
     `steps` table alone recovers the run and the suite would pass with idempotency deleted
  4. restart the worker, let it reclaim the expired lease and finish
  5. assert final status `succeeded` and output matches the no-crash baseline
  6. assert `COUNT(*) FROM llm_calls WHERE cached=false` **equals** the no-crash baseline —
     this is the no-double-billing proof, and it is the single most important assertion in
     the repo
  7. assert at least one `cached=true` row exists. Assertion 6 alone is satisfied both by a
     run that replayed the interrupted call and by one with no ledger at all that got lucky
     about where the crash landed; only the first leaves this row behind

  The scenario drives a plain `EchoProvider`, so no step returns invalid JSON and the
  repair loop never runs twice. The crash-between-a-repair-and-its-checkpoint window is the
  same failure mode a few milliseconds wide, and is covered in-process by `test_pipeline.py`
  rather than by aiming a subprocess kill at it.

## Makefile

`up` (compose up + wait for healthy + migrate) · `down` · `demo` · `test` · `chaos` ·
`fmt` · `lint` · `clean`. `make demo` must work from a clean clone with only Docker and uv
installed, and must end by printing `llmrun runs show` output.

## CI

The workflow checks the lockfile, Ruff lint and formatting, migrations, and the full suite
including chaos on Python 3.11, 3.12, and 3.13 against Postgres 17. Separate jobs validate the
optional Anthropic SDK surface without a paid call, audit all locked dependencies, and build
both distribution formats. The package job installs the built wheel outside the checkout and
runs its bundled migrations against a clean Postgres service before calling `llmrun health`.

## docker-compose.yml

Postgres 17, host port **55432** bound to `127.0.0.1` (avoid colliding with a local 5432 without
exposing cleartext development prompts on the network), user/pass/db all `llmrun`, named
volume, `pg_isready` healthcheck.

## Conventions

- Type hints everywhere; `from __future__ import annotations` at the top of every module
- Docstrings explain *why*, not *what*
- No `print()` in library code — use `logging.getLogger("llmrun.<module>")`
- Ruff for lint and format, line length 100
- Every SQL statement is parameterised. No f-string SQL, anywhere, ever.
